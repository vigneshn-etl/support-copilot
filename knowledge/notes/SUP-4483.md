## Problem

Belk users find items by VPN (vendor product number). Grid View and TY/LY Grid
View search by VPN worked, but Summary View (VPN is the number in the lower right
of the card) and History Grid Tabs (Nested View) did not, even after the config
assignee (Marikannan C) had added `searchIndexes` entries to those `.viewdefn`
files (JIRA 2026-08-21: "a few Search Index issues are still pending").

## Diagnosis path

- Mechanism confirmed from a precedent (`belk-configs@34327ab`, SUP-2975): per-view
  search fields are a `searchIndexes: string[]` in the viewdefn, e.g. `"attribute:cc_vpn:name"`.
- Ruled out a config-content mistake: audited all 90 BELK viewdefns with `searchIndexes`
  (live QA merged over repo, no drift). The 10 edited for this ticket all use the same
  `attribute:cc_vpn:name`; all 13 backing modeldefns declare it; `M_Meta.conf:796`
  defines `cc_vpn` once platform-wide.
- **Root cause (read in `assortmentui`, session analysis):** the Zod viewdefn
  schemas for Summary View and Nested View did not declare `searchIndexes`
  (`configuration-schemas/schemas/viewdefns/viewdefn.ts`, `zSummaryViewDefn` ~L280,
  `zNestedGridViewDefn` ~L137), so `.parse()` silently stripped the key and
  `SummaryView.selectors.ts` fell back to `externalGridSearchFields` (name / description
  only). No error, no warning. Grid and TY/LY schemas declared it, so they worked.
  History Grid Nested View additionally ignored search fields: `ListGridPair.selectors.ts`
  did not forward the computed `searchFields` to `listDataTreeToAgFlatTree`.
- Checked TRD for a workaround: none. TRD has 76 viewdefns with `searchIndexes`;
  its only SummaryView screen with it is likely just as inert; zero of 44 NestedView.
  SUP-4466 (TRD worklist-id search) is a good precedent for the pure-config mechanism on
  `ConfigurableGrid`.
- Session verdict (2026-08): not fixable from `belk-configs` alone.

## Fix

Two parts:

1. Platform (`assortmentui`, ticket INT-6195, commit 7acaa3eea, merged 2026-08-24,
   branch `dev`): added `searchIndexes: z.array(z.string()).optional()` to the schemas
   for Summary View, Nested Grid, Pareto Summary, Productivity, Canvas View and
   Publish Allocation grid; passed `searchFields` into `listDataTreeToAgFlatTree` in
   `ListGridPair.selectors.ts`. SUP-4483 is linked "blocked by INT-6195" (2026-08-24).
2. Config (`belk-configs`, a0e5cda by marikannanc-05 2026-08-26, PR #318 merged 2026-08-27; 18 files):
   `searchIndexes` added to the HS / Asst Build / Asst Analysis grid, TY/LY, nested and
   summary viewdefns (TD_ variants included) with `attribute:cc_vpn:name` plus
   name/description/style/stylecolor fields; `AssortmentFit.modeldefn` and
   `TD_HistoryFit_quick.modeldefn` gained the needed member and
   `attribute:sty_vpn_final:name` fields; `AssortmentBuildStyleColorSummaryDetails.viewdefn`
   now shows `attribute:sty_vpn_final:name` as the right-side value (replacing the MSRP
   line there) and searches on it.
   Follow-up 411bd30 (PR #324, 2026-08-28, branch `SUP-4483_stylepane`):
   `TD_AssortmentStyleDetailsPane.viewdefn` dataIndex `attribute:sty_vpn:name` ->
   `attribute:sty_vpn_final:name`, because the Top Down style pane showed VPN blank.

## Knowledge gained (techno-functional)

**Technical:** A viewdefn key not in its component's Zod schema is dropped silently;
"config looks right and live but the feature does nothing" should send you to
`configuration-schemas/schemas/viewdefns/viewdefn.ts` before changing config. Search fields fall
back to a hardcoded default list when `searchIndexes` is undefined.
Belk has two VPN attributes (`cc_vpn` and `sty_vpn_final`); the Top Down style pane and
summary card use `sty_vpn_final`.

**Functional:** VPN is how Belk merchants recognise a vendor's item, so search on it
has to work on every review/analysis screen in both Top Down and Bottom Up.

## Gotchas
