## Problem

Torrid wanted the Visual Line Plan tab (Style Color Review and Style Review)
available in the Top Down perspective, copied from the Bottom Up version
delivered in SUP-4140 (dependency), with Division / Department added to the
group-by list, channel breakouts (Omni / Stores / ECOM) for receipts, sales and
APS, and a Style ID header with description and aggregated Unit Receipts %.
Sized "Small"; estimate on JIRA 2026-06-18 was at most 1 hour.

## Diagnosis path

No investigation needed; it was a mirror of the BU config. Points worth noting:

- Tabs are declared in `uidefn/conf/AssortmentUiConf.confdefn` with an
  `inPerspectives` list. Both Visual Line Plan tabs (`pathSlot: visual-line-plan`
  = Style Color Review, component SummaryView, and
  `pathSlot: visual-line-plan-style` = Style Review) had only `"bottom-up"`.
- Group-by lists are viewdefns. Top Down variants are picked by an app-aware
  `TD_` prefix: the QA application log captured for this ticket shows
  `appName=TDAnalysis, id=AssortmentStyleColorVisualLinePlanGroupBy` resolving to
  `/uidefn/view/TD_AssortmentStyleColorVisualLinePlanGroupBy.viewdefn`.
- Inferred: `TD_AssortmentStyleReviewGroupBy.viewdefn` already existed in the repo,
  so Style Review needed only the perspective flip; the new TD group-by file
  was only needed for Style Color Review.

## Knowledge gained (techno-functional)

**Technical:** Enabling a screen in another perspective is a confdefn
`inPerspectives` change; per-perspective view variants are `TD_<name>.viewdefn`
files resolved by `appName` (TDAnalysis). The group-by dropdown is a separate
viewdefn with `type: groupBy` and `groupingKey` / `dataIndex` entries.

**Functional:** Visual Line Plan is the picture-based style/style-color card view
used in Investment Reviews; Top Down users review at Division/Department level
across channels in a single view, which is why those levels go first in the
group-by.
