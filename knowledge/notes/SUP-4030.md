## Problem

Looker needs MFP plan data. The reporter assumed the existing production MFP outbound (`.../outbound/integrations/mfp/<date>`) could just be tweaked,
but that report is actuals-only, so this became a new extraction + orchestration build (Vignesh, JIRA 2026-05-11; confirmed by the reporter).

## Fix

`etl-trd-batch` branch `SUP-4030-mfp-plan-outbound`, merged via PRs #204 (2026-07-06) and #215 (2026-07-08), commits `ffc6690`, `8f94edd`, `37dfffc`, `bb97b7b`:
- `pgsql/mfpapsync/mfp_plan_data_outbound_daily.sql` - builds `plan_data_export`: latest plan row per (product, location, time, module, version) by `created_at` from `mfp.plans`
  for versions `op/rp/sv1`, module `bottom_up`, `time >= year-3` and `< year+3`; joins `mfp.plan_data_wide`; money columns divided by 100; calc metrics expanded inline;
  `\copy` to `trd_plan_data_wide.tsv` with `DELIMITER '|'`, header, `FORCE_QUOTE *` (file name stays `.tsv`).
- `mfp_plan_data_outbound_daily.sh` (repo root) - runs the SQL, renames to `trd_plan_data_wide_<timestamp>.tsv`, `gsutil cp` to `${SELF_DESTINATION_MFP_BUCKET_PATH}/<YYYYMMDD>/`, Slack notices.
  `bb97b7b` replaced a separate exit-code check with `if ! gsutil cp ...`.
- `run_daily.sh` calls the script; `weekly.sh` gets `execute_mfp_plan_data_outbound` before `execute_completion_email` in each start-at branch.

## Knowledge gained (techno-functional — required)

**Technical:** Plan outbound reads Postgres `mfp.plans` (versioned, `created_at`) joined to `mfp.plan_data_wide`; ids must be taken from the newest row per
key. Values are stored in cents (the SQL divides money by 100). Postgres `\copy ... FORCE_QUOTE *` with `DELIMITER '|'` is how the pipe format was delivered.
**Functional:** The plan versions in `mfp.plans` are SV1-SV5, SAVE, OP, RP and WP (JIRA 2026-06-09); this outbound ships SV1, RP and OP. Torrid's Looker holds actuals, so S5 sends plan base
metrics at product/location/prodlife/week grain (class/selling-channel level per the draft query header) and Looker rolls up; future-year plans only exist if planners saved them.

## Gotchas

- The existing outbound is actuals-only; do not reuse its query for plan data.
- Reporter's calc-vs-base decision flipped after QA review - settle metric scope (and keep the formula reference) before building.
