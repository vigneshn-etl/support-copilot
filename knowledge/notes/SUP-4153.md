## Problem

Torrid planners reconcile receipt plans between MFP (MFP-RP) and the AP plan
rollups in the Financial Reconciliation grid, but the grid showed only
receipts. Asked: (1) Unit On Order and C$ On Order (Plan / MFP-RP / Var MFP-RP)
directly after the matching Receipts sections, (2) a new "First MD Units"
section (Plan / MFP-RP / Var) between "FP U EOP WOH" and "Ttl R$ Sales".
Change request, no existing client had it.

## Diagnosis path

- Early estimate (JIRA 2026-06-18, Gautham) defined "planned MD week" as
  `min(time) where prodlife='MD'` in `p_dc_assort_pd_month`. Superseded: the
  pivot comment says it was validated as wrong because it silently floored to
  planCurrent for items whose real markdown start predates the plan window.
  Final source is `erlstmkdnwk` from `ma_stylecolorchannelattributes`.
- Business definition of First MD Units was ambiguous (own-MD-week BOH summed
  vs. BOH at the period's first week). Asked on JIRA 2026-07-03; answer
  2026-07-07: sum each item's BOH at the week it goes to MD (3 items MD in W1
  with BOH 300 + 3 items MD in W2 with BOH 300 = March 600). Jatin Rana pushed
  back that this breaks the generic "BOH of period = BOH of first week"
  definition but agreed to implement as asked (JIRA 2026-07-07/08).
- Defect SUP-4316 (QA, 2026-07-10): Recon MFP-RP did not match MFP TY-RP.
  **Not a code defect.** QA's ETL crontab had no scheduled TRD jobs, so
  `mfp_to_ap_sync.sh` (refreshes `trd_p_mfp_tbl` in ClickHouse, the source of
  every MFP-RP column) never ran; stale data happened to equal SV1. Running it
  manually made Recon MFP-RP equal TY-RP (e.g. Feb W1 Unit On Order 206,753 ->
  3,029); AP Plan values unchanged. (JIRA 2026-07-11)
- Second round (JIRA 2026-07-15, Nicole): totals right but First MD Units were 0
  when the Recon was grouped by Channel. **Root cause:** `AP_FIRST_MD` selected
  and grouped by `a.channel` (the dedup key column) instead of `a.selling_channel`.

## Fix

Config only, repo `trd-configs`, branch `SUP-4153-mfp-reconciliation-metrics`:

- `pivot/ReconciliationNestedSTD.pivotdefn` (ca1b110, 0299ff2 2026-07-08):
  new `ONORDER_BASE_${SESSION_ID}` (from `trd_p_onorder_by_po`, with a helper
  `STYLECOLOR_CLASS` table mapping `parent_id` -> class; `price_status='FP'`
  gives the FP/Ttl split like prodlife on receipts), new `AP_FIRST_MD_${SESSION_ID}`,
  MFP side adds `on_order_u/c` and `perm_md_inv_u_edit`, new columns threaded
  through every UNION branch of the BASE / LEVEL1 / LEVEL2 / ROOT hierarchy tables,
  3 new Var calcs: `case when mfp_x > 0 then (plan_x / mfp_x) - 1 else 0 end`.
- `uidefn/view/FinancialReconciliationGrid.viewdefn`: three new column groups
  (Unit On Order, C$ On Order, First MD Units; renderers thousand / usMoneyNoCents / arrowPercentTwoDecimal).
- b921803 (2026-07-16, "SUP-4153/SUP-4316"): `a.channel` -> `a.selling_channel` in
  select and GROUP BY of `AP_FIRST_MD` (2-line change).
- Promoted to production 2026-08-07 (JIRA comment). PR link not recorded here.

## Knowledge gained (techno-functional)

**Technical:** Recon pivot metrics must be added to every UNION branch of every
hierarchy table (observed: BASE, LEVEL1, LEVEL2, ROOT) with identical column
order, zero-filled where a branch has no source; ClickHouse 21.4 does not
support `USING` across chained joins, so lookups are materialised as their own
Memory tables (`STYLECOLOR_CLASS`) and never chain more than two joins.
Every MFP-RP column reads `trd_p_mfp_tbl`; check ETL freshness before calling a
mismatch a config bug.

**Functional:** First MD Units = units on hand (BOH) of each item at the week it
is planned to go to markdown, summed (additive) up week -> month -> quarter, and
compared to MFP's "Perm MD Inv Unit, FP". It is deliberately not the period's
opening BOH. On Order = open PO units/cost rolled up from style color, compared
to MFP on-order, with the same Var MFP-RP calc as receipts.

## Gotchas

- "channel" vs "selling_channel": `channel` is the dedup/location key; grouping by
  it zeroes the metric when the Recon is drilled by Channel.
- QA ETL has no cron; MFP sync must be run by hand before validating MFP-RP.
