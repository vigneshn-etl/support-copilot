## Problem

Evereve (EE) asked for the grid search box to clear when navigating among four
Allocation views (Set Constraints > Store Constraints, Stylecolor X Store
Constraints; Review Allocations > Review By Store, Review by Stylecolor). The
ticket was cloned from the TRD equivalent (SUP-3677) and depends on platform
feature INT-5567. Task type, config component; QA URL on the EE QA tenant.

## Diagnosis path

Session 2026-09-10 (analysis plus a local edit; the ticket was assigned to
Shanmuga Priya S, not to the session owner):

- Prior art search: none in notes or JIRA for the symptom.
- Linked ticket INT-5567 (status Reviewed, available to deploy at the time) is
  the platform feature: confdefn `workflows: { <key>: { clearSearch } }` and a
  per-view `componentProps.workflow: "<key>"`. Confirmed present in the
  `assortmentui` clone: `configuration-schemas/schemas/confdefn.ts`,
  `confdefnView.ts`, and the reducer in
  `assortment-ui/src/components/Subheader/Subheader.slice.ts`
  (`setActiveWorkflowKey`: clears when `clearsSearch && prevKey !== nextKey`).
  Darwin is not involved (confdefn is opaque JSON to it).
- **Root cause:** the capability existed but EE config never adopted it: none
  of the four viewdefns had a `workflow` key and `AssortmentUiConf.confdefn` had
  no `workflows` map, so every screen used the shared `baseWorkflow` default and
  the key never changed across navigation.
- Prior art on another tenant: `trd-configs` already tags the same four screens
  with `"workflow": "allocationStore"` and defines `allocationStore.clearSearch`
  true. EE fix mirrors it.
- Open question raised, not answered in the record: other confdefn variants
  (`AssortmentUiConf_LG*`, `_With_Archives`, `_TEST`) and the Review Archives
  view were not part of the four named screens, so not changed.

## Knowledge gained (techno-functional — required)

**Technical:** "clear search on navigation" is a platform key-change rule, not a
per-view flag. Each view resolves to a workflow key (its own
`componentProps.workflow`, else `baseWorkflow`, which always clears). On
navigation the destination's `clearSearch` applies only when
`prevKey !== nextKey`. Views sharing a key retain search between them; moving
between that bucket and any other clears on both entry and exit. Before the
fix no EE screen had a key, so the key never changed and nothing cleared. Reuse
per client by copying the TRD pattern; the config schema is in
`confdefn.ts`/`confdefnView.ts`.

**Functional:** in Allocation, planners filter by a style or store while setting
constraints; carrying that filter into a different grain (Review by Store vs by
Stylecolor) silently hides rows. The agreed behavior is that search persists
within the same working mode but resets when the planner changes mode.

## Gotchas

- Reporters testing "clear on navigation" will see search persist between two
  views that share the key; that is by design, not a defect.
- Several `AssortmentUiConf_*` variants exist in the EE config repo; confirm
  which is live before copying a change into all of them.
