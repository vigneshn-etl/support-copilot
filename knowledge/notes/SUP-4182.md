## Problem

AEO announced three new trailing columns on the StyleColor Attributes inbound
file (`S5ProdAttrStyleClr_`). S5 had to carry them through every layer
(Vertica raw/in/rej tables, the `_ma_` attribute table and its `_existing`
round-trip table, Postgres, ClickHouse) for all four AEO-family tenants.
Delivered in the PR merged 2026-06-22; DDL was exercised on the AEO internal-QA
processor (unit-test log file dated 2026-06-19).

## Knowledge gained (techno-functional — required)

**Technical:** a new inbound attribute column touches ~7 places and the
**order is positional**: `aeo_table_mappings.json` `ColumnNames` must match the
file's column order; REJ tables carry `REJECT_REASON` last, so adding a column
means RENAME `REJECT_REASON` -> new column, add the rest, then re-add
`REJECT_REASON`. In PG a view cannot gain a mid-list column via `CREATE OR
REPLACE`; DROP+CREATE. In CH, ALTER the `_tbl`, then DROP+CREATE the
Distributed wrapper and the `_view`. Same recipe was reused for TRD in
[SUP-4311](SUP-4311.md). AEO fixes replicate to UNS/TSN/AER (all four
subfolders were changed in one PR).

**Functional:** floorset is the delivery window a stylecolor lands in (the
inbound already carries ORIGINAL/ACTUAL_FLOORSET and `_YOY` variants); the new
"end floorset" fields extend that to when a color's floor life ends. The values
come from AEO, may be blank initially, and (inferred) only become useful once a
view/config binds them, which is not part of this ticket.

## Gotchas

- Run DDL on every tenant (aeo, aer, tsn, uns) and every engine; missing one
  breaks the weekly load for that tenant.
- Vertica `TRUNCATE TABLE a, b, ...` (comma list) gave a syntax error in the
  sibling SUP-4183 session logs; run DDL/TRUNCATE one statement at a time.
- The `_existing` tables hold round-trip data; add columns there too or
  `load_existing.sql` COPY will misalign.
