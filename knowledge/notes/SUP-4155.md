## Problem

Boden (BD) MFP market factors are supplied with at least 5 decimals (e.g. `1.01714` for
`CT138 / MK10162-TE586-GBP / FP / 2026-W27`). The UI shows 2 decimals but holds more in the
back end, yet the MFP download and the calculations only used 4 (`1.0171`), so `Gross CTP with
MF` was slightly off. Split from SUP-4004; high priority because the
new factors were to go live in prod on 6/5 for users on 6/8. Reported by Olga Gervits.

## Diagnosis path

Owner's lineage (from the "Understanding SUP-4155" page), confirmed against
`etl-bod-batch` (`origin/etl-prod-2025`):

`constant_tables/bd_market_factor.csv` -> `bd_factors_stage` (`float8`, full precision,
`vsql/weekly/mfp/02_mfp_factors.sql`) -> `bd_mfp_sales_inventory_class_mtc_prep_factored`
(`factor_grossdemand_asp float8`) -> **`FINAL_EXPORT_TEMP_2`** (Vertica,
`vsql/weekly/mfp/04_mfp_final_export.sql:107`: `factor_grossdemand_asp numeric(16,4) DEFAULT 0`)
-> `bd_mfp_sales_inventory_class_mtc_prep_final_with_forwards.csv` (MFP export) ->
Postgres `mfp.actual_wide`.

- The constant file holds `1.01714`; the staging/factored steps are `float8`, so nothing is lost
  there.
- **Root cause:** the final-export staging table declares the factor as `numeric(16,4)`, so
  Vertica rounds to 4 decimals on insert; everything after (CSV, `mfp.actual_wide`) only ever sees
  `1.0171`. Postgres value observed: `1.0171`.
- Display is separate: `metrics.json` (`gross_ctp_rev_act`) defines how the UI formats the value
  (it showed `1.0171`); it was not the cause of the lost digits.
- Not a frontend truncation: the data was already rounded at load. (Inferred from the lineage
  above; the frontend config was not re-read.)

## Knowledge gained (techno-functional — required)

**Technical:** In Boden's MFP weekly export the precision of a column is decided by the
Vertica staging DDL (`FINAL_EXPORT_TEMP_2`, mostly `numeric(16,4)`), not by the inputs. A
`DEFAULT 0 numeric(16,4)` column rounds on insert, and the repo script drops/recreates the table
every run, so a one-off `ALTER` in an environment is overwritten by the next weekly unless the
`CREATE TABLE` in `04_mfp_final_export.sql` is changed too. Check this DDL first for any
"value has fewer decimals than the source" ticket.

**Functional:** Market factors (`factor_grossdemand_asp`) feed `Gross CTP with MF` (gross demand
ASP/CTP revenue) in MFP; planners expect the factor Boden sent
to be applied exactly (5th decimal included). Rounding to 4 decimals shifts `Gross CTP with MF`
slightly (the ticket reports the calculation using only the 4-digit value).

## Gotchas
