## Diagnosis path

Long session, several genuine bugs found beyond the original ask — in
order encountered:

- **HOCON/FreeMarker scope-var bug** (repeated from an earlier Cat Recap
  fix): `${TENANT_ID}`/`${SESSION_ID}` inside a `params.X="""..."""` block
  does not resolve in the "mother_of_All_Pivots" bespoke pivot family (no
  shared `.ftl` include, so no second interpolation pass). Fix: move
  scope-var-dependent columns out of `params.X`, add them as inline
  `SELECT` columns in the `CREATE TABLE` statement instead.
- **ClickHouse UNION ALL type mismatch**: `countIf(DISTINCT time,
  strcntwk>0)` returns `UInt64`; every sibling branch was `Float32` →
  "no supertype" error. Fix: `CAST(countIf(...) as Float32)`.
- **`tot_weekcount` sum-vs-max rollup bug** (the big one) — proven live via
  screenshot (WOH=8022.3 on a department rollup): `BASE_METRICS_UNION`
  layer (merging UNION branches of the *same* row) correctly used `sum`
  (sum-of-zeros-plus-one-real-value = that value). But
  `BASE_METRICS_AGG_UNION`/`_SUM` layers (re-aggregating *across different
  stylecolors* for a grouped/rolled-up row) also used `sum`, which inflates
  weekcount by item-count. Fixed to `max` at the AGG_UNION layers only, in
  both TD and bottom-up `HistoryGrid_quick/detail.pivotdefn`. Initially
  reasoned (wrongly) that other pivot families (`HistoryFit`/TY-LY/Flow
  Type) were safe because a param block wasn't *explicitly* referenced —
  wrong: darwin's engine consumes `params.X` blocks *implicitly*, so
  "not referenced in text" ≠ "not used."
- **Frontend Group-By rollup formula bug** (assortmentui): `avg(` in a
  `.viewdefn` formula silently produced blank cells on Group-By. Root
  cause: `AgDataFormat.ts` uses a bare `mathjs` instance with no
  `avg`/`count` registered (unlike other components' properly-configured
  instance) — `avg` gets misclassified as a data column, then fails when
  called as a function, caught silently. Config-only fix (no frontend
  code change needed): swap `avg(` → `max(` (not `mean(` — mean is a
  registered function and would have "fixed" the crash, but max is the
  *correct* aggregation choice here, same reasoning as the weekcount bug
  above).
- **"Style Color Summary (LTD)" popup mismatch investigation** —
  Avail Inv U showed 1,372 in the live Grid (scoped to selected weeks) vs
  6 in the popup, for the same stylecolor. Root cause: the popup
  (`HistoryStyleReview.pivotdefn`) is a thin passthrough reading straight
  from `history_am_model_tbl`, a **pre-materialized, Life-To-Date batch
  table** rebuilt wholesale every week by `510_ch_am_prep_final_with_style.sql`
  — no time/scope filter at all. Confirmed via the table's own week-window
  logic: `time IN (select ty_week_id from blk_ty_ly_lly_week_...)`, bounded
  only by `cctytime <= (select week from blk_ytd_qtd_mtd_mapping where lw=1)`
  — an upper bound only, no lower bound. Live-verified the actual gap:
  batch's "last completed week" was 102 weeks after the grid's selected
  scope. Not a bug — LTD panel and scoped grid are different metrics by
  design.
- **`fp_sell_thru_pct` ETL bug** found via the above: denominator used
  `fp_last_value_eoh_u` (FP-only inventory) instead of the agnostic
  `avail_inv_u` already used by `sell_thru_pct`. Fixed in
  `510_ch_am_prep_final_with_style.sql:3076`.
- **Wrench column order** — two DIFFERENT ordering rules depending on
  ticket/module: this ticket wanted `ST% → FP ST% → FP WOH → WOH`
  consecutive in Hindsighting views (7 of ~14 candidate files were wrong —
  fixed). SUP-4628 (Assortment) instead wants `FP ST%` after `ST%` but
  `FP WOH` *before* "BOH U" and `WOH` *after* `FP WOH` — not a consecutive
  block. Don't reuse the Hindsighting pattern by habit.
- **VPN attribute lineage** (tangential, raised by a user question, not
  yet actioned as a fix): `attribute:X:Y` bindings are resolved by darwin's
  `AttributePostProcessor` as a *separate* decoration pass after the
  pivot's own SQL runs, gated by (a) the attribute being declared in the
  `.modeldefn`'s `model` list, and (b) a live join against a per-attribute
  table (`blk_ma_stylecolorattributes`, `blk_ma_styleattributes`, etc.),
  keyed by dimension/level columns. Confirmed via live QA log
  (`AttributePostProcessor` INFO/DEBUG lines) that the Assortment Style
  Pane binds `attribute:sty_vpn_final:name` (from `blk_ma_styleattributes`,
  style-level) while every other working VPN display in the UI binds
  `attribute:cc_vpn:name` (from `blk_ma_stylecolorattributes`,
  stylecolor-level) — a different field/table/grain, not a broken join.

## Knowledge gained (techno-functional — required)

**Technical — confirmed formula set (Nicole-approved 2026-09-01):**
```
tot_avail_inv_u = tot_last_value_eoh_u + tot_last_value_eoh_intransit_u + tot_net_sls_u   (agnostic — EOH + ALL sales, not just FP)
sell_thru_pct    = tot_net_sls_u / tot_avail_inv_u        (unchanged in shape from pre-ticket formula)
fp_st_pct        = fp_net_sls_u  / tot_avail_inv_u
woh              = tot_avail_inv_u / (tot_net_sls_u / tot_weekcount)
fp_woh           = tot_avail_inv_u / (fp_net_sls_u  / tot_weekcount)   ← Nicole's worked example: (100+50)/(40/4)=15, matches exactly
tot_weekcount    = countIf(DISTINCT time, strcntwk > 0)     ← Nicole confirmed: keep this condition
```
For GROUPED rollups (department, class, multi-stylecolor Group-By), use
`max(tot_weekcount)`, never `sum()` — sum inflates by item-count. Reference
implementation: `pivot/HistoryFit.pivotdefn:175-212`.

`pivotdefn` files are resolved by **filename**, not by their internal
`id="..."` field (confirmed in darwin: `ConfigDefnLoaderTransportImpl.java`,
`KNOWN_PATHS.put("pivotdefn","/pivot")` — generic path-based lookup). Some
files (e.g. `pivot/StyleChannelReview.pivotdefn`) carry a stale/copy-pasted
`id=` that doesn't match their filename — cosmetic, not a routing bug, but
confusing when grepping for "the HistoryFit pivot."

**Functional:** ST%/FP ST% measure sell-through against the SAME
price-agnostic total available inventory — the FP/agnostic split lives
entirely in the numerator (which sales count), never the denominator
(how much stock was available). WOH/FP WOH are "how many weeks could
current inventory sustain the recent sales rate" — same agnostic
inventory base, FP-only vs total sales rate in the denominator. The
Style Pane ("LTD") is a fundamentally different metric from the same-named
scoped grid column: it reflects the item's state as of the last completed
batch-run week, life-to-date, completely independent of whatever date
range a user has selected in the UI — not a bug when they disagree.

  (FP-only inventory denominator) — flagged, not yet fixed, in scope for
  SUP-4628 alongside the new-metric work there.
- Darwin's `AttributePostProcessor` logs `"requested a set of unknown
  attributes"` (invalid/unresolvable ids, silently dropped) and
  `"requested attributes that are ineligible due to missing columns"`
  separately — check both when chasing a blank `attribute:X:Y` field; a
  blank value with neither log line present usually means the join ran
  but the source table's row is genuinely null, not a config bug.
