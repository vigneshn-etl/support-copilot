## Problem

Belk's intraday batch expects three file types per drop in the intraday inbound
GCS folder: `S5SpecByDesignSeason`, `S5SpecStyleAttributesbyDesignSeason`,
`S5SpecStyleColorAttributes`. Belk may send several complete sets in one drop.
If any file was missing or the counts did not match, the batch failed partway
(see duplicate SUP-4244), on-call was paged, and someone had to move the files
out of the way (so the next run does not fail) and email Belk manually.
Requirement (Chris McGinley, 2026-07-02): validate up front; if invalid, email
Belk which files are missing, archive the files, post Slack, and do not page.

## Diagnosis path

Feature work, no bug hunt. The design points that mattered:

- Where to gate: before any processing, i.e. at the top of `run_intraday.sh`,
  because `bash/intraday/process_spec_style.sh` pairs the files by sort order
  (1st DesignSeason with 1st ColorAttr, etc.) and assumes matched sets.
- "Valid" = counts of the 3 types are equal and non-zero (3, 6, 9... files with
  every type represented in every set). This is a count check only; file
  content/set membership is not verified (inferred from the script).
- How to fail without paging: needed a distinct exit code the callers could tell
  apart from a real error.

## Fix

`etl-belk-batch` commit `125dda9` on local branch
`SUP-4301-belk-intraday-upgrade-prod` (the commit is not on any remote branch
in the clone; PR/merge not recorded in session):

- `bash/intraday/00_pre_check_intraday_files.sh` (new) - `gsutil ls` counts of
  each type; equal and >0 -> exit 0. Otherwise a failed cycle: zero files ->
  "no files received" (nothing to archive); partial -> compute per-type shortfall
  vs the highest count and `gsutil mv` all `*.dat` to `intraday_archive/`.
  Posts Slack (`S5SlackBot.py`) and emails Belk (`MailClient.py` with the new
  template), then `exit 100`. The `|| true` on each count is required: under
  `set -o pipefail`, no gsutil matches would otherwise abort the script.
- `run_intraday.sh` - runs the pre-check first; passes 100 through, any other
  non-zero is an unexpected error.
- `intraday.sh` - on exit 100: save the log copy, Slack the log path, back up
  files, clear the flag file, `exit 1` (run is marked failed) but skip
  `failure_notify_oncall`.
- `python3/MailClient.py` - new reason `3: "Missing File(s) From Client"`.
- `mail_template_intraday_missing_files.txt` (new) - HTML email with missing
  list and archive location.

## Knowledge gained (techno-functional - required)

**Technical:** Convention for "handled data failure": a script exits 100 and the
wrapper maps it to "mark run failed, notify the client, skip on-call page".
Intraday on Belk is cron-driven (every ~30 min) and decides readiness by file
presence in GCS, so a bad drop poisons the next cycle unless files are archived.
`MailClient.py` is positional: job index 2 = Intraday Batch, status 3 = Failed,
reason 3 = Missing File(s) From Client.

**Functional:** Intraday feeds Belk's PLM style/stylecolor attributes (design
season, style attributes, stylecolor attributes) into planning. An incomplete
drop is a client-side data problem; the right response is to tell Belk what to
resend, not to wake support.

## Gotchas

- Behaviour change for Belk: the cycle still fails, but on-call is not paged;
  Belk must resend a complete set (all 3 types, matching counts) to be
  processed on a later cycle. Nicole notified Belk before deploy.
- Zero files received is also treated as a failed cycle (email + Slack) - that
  is stricter than the ticket text ("if any of 3 files don't exist") reads.
- A count match does not prove the 3 files belong to the same set.
