## Problem

Belk styles vanished from the UI after batch runs. Users exported a view on
Friday containing items that were missing Monday morning. Rows absent from
`D_Product`, so every downstream screen lost them.

## Diagnosis path

- Affected products traced in `blk_ma_stylecolorchannelattributes` /
  bulk-upload arc tables — records existed in PG before batch.
- Inspected the PG→Vertica export file (`blk_d_product_existing`) on the
  batch host: affected style + stylecolor exported as **4 records instead
  of 2**.
- **Root cause:** users uploaded style descriptions containing carriage
  returns (via bulk-upload template; copy/paste bypasses template
  validations). The PG export wrote such records across 2 lines, Vertica's
  load rejected/split them, and the products fell out of `D_Product`.

## Fix

Input validation on free-text fields at upload: style description limited
to letters, numbers, space, underscore, hyphen (matching Style Edit rules),
then extended to all free-text template columns. Iterated once: forward
slash re-allowed for merch_color_name because production data legitimately
contains it.

## Verification

QA re-upload with the offending template: bad characters rejected with a
clear message; a `/` in merch color accepted after the amendment.

## Gotchas

- **Copy/paste bypasses spreadsheet template validations** — server-side
  validation is the only real gate for bulk uploads.
- Any "rows disappeared after batch" symptom: check the intermediate
  export file for line-count vs record-count mismatch (embedded newlines,
  quotes, delimiters in user text).
- When tightening character validation, audit existing production values
  first — legitimate data may already violate the new rule (the `/` case).
