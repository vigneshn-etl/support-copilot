## Problem

On the Torrid Upgrade environment, Group By "Original Retail" in the configure wheel showed
"undefined" for stylecolors whose Orig Retail was populated (Style Color Review > Grid View
showed it fine). Follow-on to [SUP-4311](SUP-4311.md) / SUP-4152, which added the text mirror
`cc_orig_unit_retail_char` (`'$'||cc_orig_unit_retail`) because Configure/GroupBy cannot use
float columns.

## Diagnosis path

- Grid View vs Nested Attribute (log comparison): Grid View reads `attribute:cc_orig_unit_retail_char:name`
  live from **Postgres** `trd_ma_stylecolorattributes` via `AttributePostProcessor`; the broken views read it
  inside the pivot SQL from **ClickHouse** `trd_stylecolor_hier_attr`, picking `(product, max(updated_at))` per product.
- Jatin's hypothesis "add the column to FlowSheetPlanPivot.pivotdefn": first **rejected** (the attribute binds via
  `M_Meta.conf:746` -> Postgres/attribute tables, no pivotdefn references it) - later turned out to be right for a
  different reason (below).
- Hypothesis "SUP-4311 migration had no backfill, so old rows are NULL": QA PG had 107,619/107,619 rows in sync
  -> not the cause on QA. (Migration did indeed have no backfill UPDATE; not the bug here.)
- **Dead end:** Upgrade PG returned 0 rows for `product IN ('11853893','16411595')`. Product keys are
  `<style>_<COLOR>` (e.g. `11853893_RICHBLACK`, per the JIRA root-cause comment), so the bare-id query was wrong
  (inferred); this had briefly pointed at a missing-row / client-id-mapping gap.
- Observed pattern on the example products: CH had a correct row ($49.90) followed 2-4 minutes later by a row with the
  same `cc_orig_unit_retail` but NULL char (later `max(updated_at)`), while PG stayed correct.
- Reproduced 3/3 in QA: edit Orig Retail in Assortment Build > Style Review > Style Edit > Price Parameters -> CH gets the
  correct row; **running Plan Queue processing from the UI** adds a second CH row ~13-25 s later with the char NULL.
  Intraday batch confirmed not running; `mfp_sync.sh` / `mfp_to_ap_sync.sh` have no references to this table.
- `conf/app_behavior.yml:7` maps `planning.assortmentPlanPivot: FlowSheetPlanPivot`, i.e. the pivot that runs during plan processing.
- **Root cause:** `FlowSheetPlanPivot.pivotdefn` ends with `insert into trd_stylecolor_hier_attr_tbl (<explicit column list>) select
  ... from trd_stylecolor_hier_attr_${SESSION_ID}` (the `-- SYNC TABLES - REQUIRED TO BE DONE FOR NON-UI PG DATA CREATIONS` block).
  `cc_orig_unit_retail_char` was missing from both lists, so every plan-queue run re-wrote the product's CH row with the char NULL.
  The session table itself is built `select *` (in `RunAllocationPlanning.pivotdefn:326`) so it already carried the column.

## Fix

- `trd-configs` branch `SUP-4449` (from `allocation-configs`), commit `54aaac0`, PR #356 (per JIRA 2026-08-03):
  `pivot/FlowSheetPlanPivot.pivotdefn`, 2 lines - add `"cc_orig_unit_retail_char"` after `cc_orig_unit_retail_cad` in the target and
  source column lists of the `insert into trd_stylecolor_hier_attr_tbl` sync.
- A third edit (the `multichannel_trd_stylecolor_hier_attr_${SESSION_ID}` column list) was added then **reverted**: that table
  is only used for scoping/joins (and the sync from it is commented "Redundant Step").
- Existing NULL rows in staging and QA were repaired with a manual SQL run (JIRA 2026-08-03; the query itself is not in the session).
- Plan for stale CH data (from session): `trd_stylecolor_hier_attr_tbl` is truncate+reloaded from PG by the intraday export
  (`pgsql/intraday/export_to_ch.sql`, `bash/intraday/11_ch_export_load_truncates.sh`), then `ch/weekly/095_sku_hier_attr.sql` rebuilds
  `trd_sku_hier_attr_tbl`; no PG update needed because PG was never wrong.
- Promoted to production 2026-08-07 (JIRA, Stephanie McDaniel).

## Knowledge gained (techno-functional — required)

**Technical:** `attribute:*:name` bindings resolve through `M_Meta.conf` to PG (decoration) in some views but through CH `*_hier_attr_tbl`
inside pivot SQL in others; the CH table is append-only with a `max(updated_at)` pick, so one bad later write masks a good earlier one.
Pivot sync INSERTs use explicit column lists: adding a column upstream (SUP-4311) is not enough until every such list is updated.

**Functional:** Orig Retail group-by buckets ($49.90, $39.50) are what planners use to cut the assortment by original price point;
"undefined" means the text mirror was NULL for that product, not that retail is missing.

## Gotchas

- Any new column on `trd_stylecolor_hier_attr` must also be added to the sync lists in `FlowSheetPlanPivot.pivotdefn` (and the CH/PG objects, appended last).
- JIRA comment 2026-07-31 (posted earlier in the session) still describes a "transient NULL, writer unknown" theory; the plan-queue sync INSERT is the later, confirmed finding.
