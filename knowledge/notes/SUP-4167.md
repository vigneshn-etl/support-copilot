## Problem

In Belk Assortment Build > Total View, planners entering a VPN ID for a
placeholder (non-PLM) style saw it stored, but it never appeared in the
Line Adopt screen, and the outbound item-creation message to RMS carried a
blank / `/N` for VPN_ID. Reporter's DB dump (JIRA description): style had
`sty_vpn_final` populated while `sty_vpn`, `sty_vpn_id_non_plm` and colour-level
`cc_vpn`/`cc_vpn_color` were empty. Total View VPN editing had already been
locked (`editable:false`) as a stopgap (Nicole Rockwell, 2026-07-10).

## Diagnosis path

- Suspected: ETL / trigger bug. Ruled out: QA live schema dump of the two
  triggers was byte-identical to git (session, 2026-08-03). No ETL/schema change was needed.
- `M_Meta.conf`: `sty_vpn_final` is `isStored: false` ("Either sty_vpn or
  sty_vpn_id_non_plm") - a derived passthrough. `sty_vpn`, `sty_vpn_id_non_plm`,
  `cc_vpn`, `cc_vpn_color` are the real stored columns.
- Total View's single "VPN ID" column had `dataIndex: attribute:sty_vpn_final:id`.
  **Root cause:** edits wrote the computed field, so neither Postgres trigger
  (`update_plm_sty_vpn` on `sty_vpn`; `update_stylecolorattributes_cc_vpn_for_non_plm` on
  `sty_vpn_id_non_plm`) fired; nothing cascaded to `cc_vpn` (what Line Adopt Non-PLM and
  the outbound message read).
- Alternatives considered and rejected (session 2026-08-10): temp column + copy trigger,
  or write `sty_vpn_final` + back-populate trigger. Both fail because
  `trig_update_sty_vpn_non_plm` is guarded by `WHEN (pg_trigger_depth() = 0)`, so a write made
  from inside another trigger never fires it.
- Asked whether one column could switch its write target per row by style type.
  Frontend trace (`EditableGrid.tsx` valueSetter / submitGranular*) says no: payload key
  comes from the static `dataIndex`; `calculation` only affects the displayed value.
  Two columns gated by `editableByCalc` is the only supported pattern.

## Fix

`belk-configs` branch `SUP-4167` (commit `4ff509c`, 2026-08-27; PR #317 merged 2026-08-27),
single file `uidefn/view/AssortmentLinePlanByFloorset_RecOverride_Cluster_Grouped_TotalView.viewdefn`:

- Replace the one column with **"VPN ID - PLM"** (`attribute:sty_vpn:id`, `inputType: validValues`,
  `observes: sty_dpt_buy_period`, `dataApi /api/v2/dependents?...source=sty_dpt_buy_period&target=sty_vpn`,
  `editableByCalc: compareNatural(type,'PLM')==0` on `sty_style_type`) and
  **"VPN ID - NON-PLM"** (`attribute:sty_vpn_id_non_plm:id`, free text, gated to `'NON-PLM'`,
  width 160). Both `disabledBy: sty_is_locked`.
- The PLM dropdown was added after QA (Dinesh Kumar, 2026-08-07) reported PLM VPN not
  reflecting in Line Adopt - it mirrors the Line Adopt PLM column config
  (`AssortmentLinePlanByFloorset_StylePLM.viewdefn`).
- **Follow-up:** merge `5a226be` ("Merge branch 'assortment-planning' into SUP-4167", conflict
  with concurrent Total View edits incl. SUP-4497) silently dropped the NON-PLM column, so PR #317
  landed only half the fix. Restored by `7eed6c6` on `SUP-4167-followup` (PR #327, merged 2026-09-01).

## Knowledge gained (techno-functional)

**Technical:** A viewdef column must bind to the stored source attribute, not a computed one:
Postgres triggers on `blk_ma_styleattributes` only fire for `UPDATE OF sty_vpn` / `sty_vpn_id_non_plm`
and cascade to `cc_vpn`, `cc_vpn_color`, `sty_vpn_final`. A grid column's write target is static
(`dataIndex`); per-row switching = two columns + `editableByCalc`. Ready to Publish
(`pivot/AssortmentItemPublish.pivotdefn`) reads ClickHouse mirrors (`blk_stylecolor_hier_attr`,
`blk_ma_stylecolorchannelattributes`) with ~10 AND-ed gates (class/subclass, `sty_vpn_final`,
supplier site, colour, merch colour name, style type, ticket price, no create date, `cc_prepublish` false),
so a correct PG write can still show an empty screen until the PG->CH sync runs.

**Functional:** PLM styles pick a VPN from a dropdown of VPNs available for the style's
department + buy period (`blk_l_dependencylookup`, maintained by `update_plm_sty_vpn`); non-PLM
placeholders type a free-text VPN. The VPN is the vendor product number RMS needs to create the item,
so a blank in the outbound message blocks item creation. Open design question left in JIRA (Nicole,
2026-08-26): PLM needs Buy Period and VPN Color too, so Total View may become read-only with a
breadcrumb, or gain those columns - decision not recorded.

## Gotchas

- Merging `assortment-planning` into a ticket branch that edits `...Grouped_TotalView.viewdefn`
  conflicts often (SUP-4497, INT-6093 etc. touch it); re-diff after every merge.
- Already-broken items need a backfill: `UPDATE ... SET sty_vpn_id_non_plm = <vpn>` re-fires the trigger
  (proposed in session; whether it was run in prod is not recorded).
- Outbound job needs `ccstylecolorcreatedate = '3000-01-01'` (set on publish); NULL silently skips.
- QA test pitfall: cyclic `item_create.sh` failed with Pub/Sub `NOT_FOUND` for the Belk outbound
  topic on 2026-08-12 (topic missing in the QA GCP project, not an auth problem); how it was
  restored is not recorded. Also `cyclic.sh` failures page on-call, so run `item_create.sh` alone when iterating.
