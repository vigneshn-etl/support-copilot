## Problem

Belk's clone feature (Select Styles > Stylecolor Attributes Clone) builds a new
style/stylecolor/size from a similar item, copying most of its data. It also
copied the publish flags `dc_publish` and `dc_publish_ecom` into `blk_p_dc_adj`,
which is wrong: a clone has never been published. Assigned to vignesh.n from
Jatin Rana's task description (2026-05-04).

## Diagnosis path

- The ticket pre-scoped the target: two Postgres procedures,
  `blk_style_clone_stylecolor_size_proc` and
  `blk_no_style_clone_stylecolor_size_proc` (introduced by SUP-3322,
  `20251015_SUP_3322_belk_*style_clone_stylecolor_size_proc.sql`).
- Reproduced in QA first (per the unit-test doc attached to the ticket): clone
  a style whose `dc_publish` is 1 (DP-365, stylecolor 476520476.230, week
  FY27_W31); after cloning and planning, the new stylecolor showed the
  parent's `dc_publish` in `blk_p_dc_adj`.
- Observed by diffing against the previous procedure text: the `blk_p_dc_adj`
  insert already nulled `published_at`, `is_prepublished`, `prepublished_at`,
  `last_prepublished`, `po_arr` (and the `_ecom` variants) but selected
  `dc_publish` / `dc_publish_ecom` straight from the source row. The
  `blk_p_dc_adj_size` insert already nulled `dc_publish`. So the gap was only
  those two columns on `blk_p_dc_adj`.
- **Root cause:** two columns in the clone INSERT...SELECT were copied instead of
  nulled, in both procedures.

## Knowledge gained (techno-functional - required)

**Technical:** Belk clone logic lives in Postgres stored procedures, not in ETL
shell/SQL scripts, and procedure changes ship as a Liquibase changeSet that
points at a full-procedure `.sql` file. Both clone procs (style path and
no-style path) must be changed together. Publish state on `blk_p_dc_adj` is a
set of columns (`dc_publish`, `published_at`, `is_prepublished`,
`prepublished_at`, `last_prepublished`, `po_arr` + `_ecom` variants); a clone
must null all of them.

**Functional:** `dc_publish` marks a stylecolor/week as already published to
the DC/PO feed. A clone inheriting it can look published (and hide from the
publish queue) when it was never sent - relevant to the PO Publish View
behaviour seen later in SUP-4455.
