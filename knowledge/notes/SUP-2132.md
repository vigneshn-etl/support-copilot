## Problem

Loft (KW group, brand LOFT) planners reported that the Mass Edit popup on
Pricing Over Time (Master and Size views) shows every item in scope: Petite
items appear in the Master view, and applying a Session Filter (Class) narrows
the grid but not the Mass Edit picker. QA was reported fixed 2026-03-13 while
Upgrade and Prod still showed it (re-confirmed 04-10 and again after the 04-16 deployment, on ANN Upgrade);
the reporter said it is consistent across brands.

## Diagnosis path

Session 2026-08-06 (triage, no JIRA writes):

- Suspect: Mass Edit bound to a single shared `massEditModel`
  (`PricingOverTime.epic.ts`, `defns.models[1]`) so session-filter temp tables
  scoped per pivot would not apply. Ruled out: Master and Size use separate
  pivots (`AssortmentFitMaster` vs `AssortmentFit`).
- Config drift ruled out: `AssortmentUiConf.confdefn` byte-identical across
  `loft-configs` (`planning_strategy`), the staging bucket and the prod bucket;
  OCI has no separate "Upgrade" bucket (Upgrade presumably shares prod config).
  Early on the wrong QA bucket was compared; the correct QA source is the
  internal-qa-config bucket. There the QA overrides of `AssortmentFitMaster` and
  `AssortmentFit` differed from base only in two metric formulas
  (`avail_inv_aut`, `net_sls_disc_pct`), unrelated; the `PricingOvertime` and
  `AssortmentUiConf` override diffs were not read in detail.
- Darwin: `Pivot2Controller` fetches the same session filter conditions for
  `fitView` (grid) and `listData` (Mass Edit), so the controller is not
  dropping filters.
- Live repro in Loft QA (browser): Class filter changed Mass Edit count 41 to
  31. First declared "QA is fixed", then retracted because only the top of the
  list was checked and the Missy/Petite half was never tested.
- QA server log SQL for `AssortmentFitMaster` product selection showed only the
  department scope in its WHERE, and the shared `assortment_products_table*.ftl`
  has no attribute-filter hook. Mass Edit payload (42 rows) mixed three
  subclasses, concluded as "bug reproduced". **Weak:** the user stated that run
  had no filter applied, so it cannot show filters being ignored; the 42 vs 20
  count gap was attributed to Companion being Top-N (inferred).
- Separate bug found while filtering: ClickHouse `Code: 70 Unexpected inf or nan
  to integer conversion` from `CAST(avg(shp_u_band) as Int32)` in
  `AssortmentFitStyleZerosMaster.pivotdefn` (lines ~683-710) when a filter
  leaves zero rows (`avg` of nothing is NaN). Same unguarded pattern in
  `StyleReview.pivotdefn` and `HistoryGrid_SnapshotRP.pivotdefn`. Not fixed.
- **Outcome in JIRA:** 2026-08-28 Aatif A Khan reviewed pivots and validated
  stylecolors against the DB hierarchy: Master/Size separation handled in the
  pivot and the session filter is respected by Mass Edit; asked for failing
  examples. 2026-08-31 reporter no longer saw it, agreed to close. Root cause
  never pinned down; "fix already in QA reached Upgrade/Prod" is the reporter's

## Knowledge gained (techno-functional — required)

**Technical:** Mass Edit item list and the main grid both call Darwin with the
same session-filter conditions; "Upgrade" shares the prod config bucket, so a
QA-vs-Upgrade split with identical config points at deployed build/data, not
config. A filter that empties a companion pivot crashes the whole request via
`CAST(NaN as Int32)`; guard with `if(isNaN(avg(x)) or avg(x) is null, 0, avg(x))`
(the guard form already used in `aeo-configs` `HistoryFit`).

**Functional:** Missy and Petite are separate size-range classes (Missy average
height, Petite cut shorter); Loft pairs them as linked styles with class codes
like 301xxx (Missy) and 302xxx (Petite). Master view should edit Missy only and
Size view Petite/size concept only, so Mass Edit must follow both the view and
the planner's session filter or price edits hit the wrong style family.

## Gotchas

- Do not call a bug reproduced from a run without the filter applied; capture
  the filtered request/response pair (pivots run in a Web Worker, so the
  browser network tab does not show payloads; use server log or DB).
- Confirm which bucket is QA before diffing live config.
- Reporter's dates drift: the scope in the ticket (2025-W20) no longer exists;
  any week with items reproduces.
