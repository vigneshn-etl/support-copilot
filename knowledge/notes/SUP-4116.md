## Problem

In Belk QA, Hindsighting > History Grid > History Grid Tabs, the Configure
modal lets the user pick three grouping levels. Several combinations failed
with backend errors in the network tab:
`Invalid aggregateBy: levelstylecolor:name`, and
`attributedefn not found: Group / Division / cc_texture_attern`; Store gave an
empty response.

## Diagnosis path

Three different causes, found over several people's work:

1. **`attributedefn not found: Group / Division / cc_texture_attern`** -
   the Configure viewdefn used attribute ids that do not exist. `M_Meta.conf`
   declares `group_name`, `division_name`, `cc_texture_pattern` (stylecolor
   attributes); the viewdefn had `Group`, `Division`, `cc_texture_attern` (typo).
   Shanmuga Priya fixed these by config (comment 2026-06-26).
2. **Stylecolor Id at Level 2** - Shanmuga found the generated
   `AGGREGATION_GROUPS(_COMMA)` contained `department,stylecolor,stylecolor`.
   In the 2026-07-28 session (QA application log, observed): request
   `aggBy=level:department:name,level:stylecolor:name,attribute:...,level:stylecolor`;
   the engine always appends a 4th level (`AGG_LEVEL_4=stylecolor`) from the
   pivot's `bottomLevels` (`ProdStd:${AGGREGATION_PRODUCTS}` in
   `pivot/HistoryGrid_quick.pivotdefn`). When the user also picks Stylecolor Id,
   the SQL has `GROUP BY department,stylecolor,<L3>,stylecolor` and ClickHouse
   rejects it: `Cannot add column stylecolor: column with this name already
   exists` (creating `<tenant>_BASE_SUM_SALES_METRICS_<session>`), followed by a
   cascading `Table ..._INV_LOCATION_... doesn't exist`; UI shows HTTP 500.
   Control run (Department / Style / Supplier Name) worked: four distinct
   values. `AGG_PRODUCT_LEVEL_COMMA` is already de-duplicated by the engine;
   `AGGREGATION_PRODUCTS/GROUPS` are not (engine defect, Java
   `PivotParamGenerator`, not visible in config text).
3. **Store** - empty response in QA only; Nicole Rockwell confirmed it is the
   large data volume in QA; works in Staging and in QA for small week ranges.
   Not fixed.

Dead ends / alternatives considered in the session:

- Porting TRD's SUP-3941 fix (trd-configs PR #323: a regex `<#if !X?matches(...)>`
  guard before manually appending `style`/`product` in `.ftl` files). It does
  fit one real place in Belk, `pivot/include/history_base_tables.ftl:28`
  (hard-coded `product, stylecolor, style, department` after
  `${AGG_PRODUCT_LEVEL_COMMA}`), but it cannot fix the blocking error, because
  the duplicate is already inside `${AGGREGATION_GROUPS}` before FreeMarker
  runs. A dedup `<#assign>` at the top of `HistoryGrid_quick.pivotdefn` was
  proposed; it was **not** what shipped.
- The 2026-07-27 reopen: the Level 2 removal Shanmuga reported on 07-22 was not
  in `belk-configs` as of the 07-28 session (the entry was still at
  `HistoryHistoryGridNestedViewConfigure_quick.viewdefn` ~lines 920-924, with a
  malformed dataIndex `levelstylecolor:name`, missing a colon).
- Gautham Vemuganti's decision: remove Stylecolor Id from the options (the view
  is already at stylecolor grain). The engineer in the session disagreed that
  this is a real fix ("removes the trigger, not the bug") - the engine-level
  dedup defect remains.

## Knowledge gained (techno-functional - required)

**Technical:** Configure-modal option `dataIndex` values must match attribute ids in
`M_Meta.conf`, else darwin throws `attributedefn not found`. For nested
Hindsighting grids the pivot's `bottomLevels` grain is appended to the user's
levels as `AGG_LEVEL_N` with no dedup; a selected level equal to the grain
produces a duplicate GROUP BY column. Level lists are per level (Level 1/3
identical; Level 2 alone carried Stylecolor Id). Same defect class as TRD
SUP-3941 (no solution note existed for it).

**Functional:** The History Grid is already reported at stylecolor level; "Stylecolor
Id" as a grouping level is redundant there and is not offered anymore. Large
Store x Stylecolor combinations are heavy on QA data volume.
