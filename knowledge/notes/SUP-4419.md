## Problem

Two bundled issues in Belk QA, Assortment Build > Recon with Targets > Total View: the
Young Contemporary dropdown and the Fine Jewelry Metal dropdown both snapped back to "NONE" after a
selection. Fine Jewelry Metal also showed "No options" (retested by QA on DP-549 BELK & CO MEMO, as the
developer had suggested a department with values - still empty).

## Diagnosis path

- Developer (Taylor Kennedy) first read it as a viewdefn editability question
  (`"editable": false` plus `editableByCalc`) and a data problem for Fine Jewelry Metal (pick a
  department that has values). Business confirmed (Stephanie) both fields should be editable here.
- Issue 1 root cause (from the fix diff): the Young Contemporary column
  (`attribute:cc_young_contemporary:id`) had its `dataApi` pointed at another attribute:
  `/api/attribute/validValues/one?appName=Assortment&ids=cc_top_length`. Inferred: the options list did not
  contain the chosen value, so the cell fell back to NONE.
- Issue 2: "is it a data issue?" - no. Triage session (2026-07-31) found in
  `conf/M_Meta.conf` that `cc_fine_jewelry_metal` had `hasValidValues: false`, while sibling categorical
  attributes (`cc_young_contemporary`, `cc_metal_type`, `cc_stone`, `cc_bridal`...) were `true`.
  `git blame` showed it was added in `53e3273` (2024-04-18) grouped with numeric/measure fields that
  genuinely have no value list (`cc_gold_mkt_fine_jewelry`, `cc_grams_fine_jewelry`...) and never corrected.
  The same flag was found independently by Vignesh in QA Meta.conf (JIRA 2026-07-31).
- Not checked in session: whether a values list is actually seeded for the attribute (QA retest passed, so it was).

## Fix

`belk-configs` commit `6745e2e` (Taylor Kennedy, 2026-07-31, branch `SUP-3878_SUP-4419_TK`,
PR #295 merged 2026-08-03):

- `uidefn/view/AssortmentLinePlanByFloorset_RecOverride_Cluster_Grouped_TotalView.viewdefn` - Young Contemporary
  `dataApi` `ids=cc_top_length` -> `ids=cc_young_contemporary`.
- `conf/M_Meta.conf` - `cc_fine_jewelry_metal`: `hasValidValues: false` -> `true`.
- The same commit also adds `attribute:cc_rcptint:id` to `LinePlanFloorset_RecOverride_Cluster.modeldefn`;
  that appears to belong to SUP-3878 (shared branch), not this ticket.

Vignesh applied the Meta.conf flip directly in QA first (2026-07-31) so QA could retest before the PR merged.

## Knowledge gained (techno-functional)

**Technical:** A Total View dropdown has two independent gates: (1) the attribute's `hasValidValues` in
`M_Meta.conf` (false = no option list for any department), and (2) the column's `dataApi.url`
`...validValues/one?ids=<attr>` which must name the same attribute. A copy-paste of a sibling column's `ids=`
yields a populated-looking dropdown whose values cannot match the field. Meta.conf lower-env changes need a PR to git.

**Functional:** Style-colour attributes such as Young Contemporary and Fine Jewelry Metal are categorical merchandising
attributes planners set per style-colour in Total View; valid values differ by department (e.g. DP-549 has Fine Jewelry
values, DP-726 does not), so "No options" in a department can be legitimate data - rule out the Meta.conf flag first.

## Gotchas

- Triage hint worth reusing: compare the flag against sibling attributes in the same `M_Meta.conf` block (`grep hasValidValues`).
- Ticket mixes two unrelated causes; verify each issue separately and in a department that has values.
