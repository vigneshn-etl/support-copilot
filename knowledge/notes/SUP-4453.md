## Problem

Belk (BLK) asked for new metrics in the five "Target Reconciliation Views" (menu
section "RECON WITH TARGETS", id `ClusterOverrideTargets`, `AssortmentUiConf.confdefn`
~L6632-6781): With Dept, With Dept-Vendor, With Class, With Ven Class, TOTAL VIEW.
Target Unit Cost and Target Unit Retail after Class (editable / mass-editable),
Target IMU after them `(Target Unit Retail (current ticket) - Target Unit Cost) / Target Unit Retail`
(non-editable), Merch Color Name after VPN, and a "% Penetration by Cluster"
column next to each cluster's Final U. The "% variance between roll and plan" part
was moved to INT-6093 (frontend renderer work).

## Knowledge gained (techno-functional)

**Technical:** One shared viewdefn drives four of the five Target Recon screens, so
any change to it hits all four at once. Some attributes (e.g. `cc_target_cost`) appear in
rows only through attribute decoration keyed on real product+location, so they are blank
on synthetic roll-up rows; compute ratios server-side in the pivot to get proper roll-ups.

**Functional:** IMU (initial markup) = (retail - cost) / retail, the planned margin at
ticket time, not re-measured after markdowns. Target IMU is planning-time (target cost
vs ticket); Rec IMU is meant to be the margin on received inventory and is expected to
diverge later (JIRA 2026-08-26) once different buys land at different costs. % Penetration by
Cluster = cluster's Final U share of the total allocation, per style row and at roll-up.
