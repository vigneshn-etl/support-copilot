## Problem

AEO Style Review and Style Color Review (Top Down + Bottom Up): the
aggregated EOH U at group-by level (e.g. Super Class) summed EOH **$**
instead of EOH **units**. Row-level values were fine — only aggregates wrong.

## Diagnosis path

- Reporter isolated it to the viewdefn config: `dataIndex` was
  `last_value_eoh_u` but the aggregate `formula` said
  `sum(last_value_eoh_r)` — a copy-paste `_r`/`_u` mismatch. Same defect in
  TY/LY variants.
- **Root cause:** viewdefn formula field referencing the revenue column for
  the units metric. Pure config-layer fix; no ETL or frontend code involved.

## Fix

Corrected `formula` to `sum(last_value_eoh_u)` (and `ty_`/`ly_` variants)
in the affected viewdefns.

## Verification

Grid export vs manual Excel sum at Super Class level (OFL Sweaters:
EOH U = 42,270; LY = 25,407). QA passed on AEO env.

## Gotchas

- **AEO has subsidiaries (UNS, TSN, AER) with their own viewdefn copies.**
  First fix landed only on AEO; QA kept failing on subsidiary URLs until
  the change was replicated to every subsidiary env. Any AEO viewdefn fix
  must be applied to all subsidiaries.
- Pattern to grep for proactively: `dataIndex` metric suffix not matching
  the `formula` column suffix (`_u` vs `_r` vs `_c`) across viewdefns —
  this class of typo likely exists elsewhere.
