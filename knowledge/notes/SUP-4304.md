## Problem

EXP style-color `007434052-00012` (S5 id `4b4e93fa-222e-4a50-b636-f07c78a767d3`, location
`GP-01`) had negative on-hand and no sales. Its `exitdate` (`2026_W34`) had not passed, yet it
was missing from every Assortment View and from "Add Existing Style Colors", so the buyer
could not re-buy it. A PO was due Monday 2026-07-06, hence blocking. Reporter: Nicole
Rockwell (ticket created 2026-07-02, prod).

## Diagnosis path

- The reporter proposed the fix: set `exitdate` into the past (`2026_WK20`) and
  `record_state = 1`. The work confirmed the update was **safe**, not why the screen
  excludes the item (see Gotchas).
- Listed the triggers on `exp01_ma_stylecolorchannelattributes`: none raises an exception,
  so the update is not blocked. Only two fire for this change:
  `ca_1_trigger_on_update` -> `store_eligibility_triger_chetan()` (rebuilds
  `exp01_a_assortment`) and `trigger_for_time_indx_update` -> `update_week_indxes()`
  (recalculates `exitdate_indx`, `mkdnwks`...). Markdown/floorset/lifecycle/sizerange/
  pricing triggers do not fire (their trigger columns do not change).
- Ruled out needing to pre-adjust `plan_current` (`2026_W23`): trigger `WHEN` clauses compare
  the **old** values and `old.exitdate (W34) > old.plan_current (W23)` was already true.
- Ruled out the known latent bug in `store_eligibility_triger_chetan()` (`temp_old` not
  filtered by `plan_type`, which duplicates non-`plan` rows on rebuild): query for
  `plan_type != 'plan'` duplicates on this product/location returned 0 rows.
- Pre-state: `exp01_a_assortment` had 9 `plan` rows (floorset months 2025-12 to 2026-08);
  `2026_W20` exists in `exp01_d_time` (`indx = 569`).
- ClickHouse mirror: `exp01_ma_stylecolorchannelattributes` is synced **only by the daily
  batch** (`pgsql/daily/export_to_ch.sql` -> `bash/daily/11.2_update_hier_attr_stylecolorchannel.sh`),
  which drops/recreates the `_tbl` plus its Distributed table and bulk-loads. The table is a plain
  `ReplicatedMergeTree` (zero `ReplacingMergeTree` in the repo), so a manual insert appends.
- Downstream CH consumers (`ch/weekly/edw_extract_v3.sql`, `extract_failed_plan_items_from_ch.sql`,
  `plan_snapshots.sql`, `ch_weekly_bulk_plan_batch_validations.sql`) dedupe with
  `max(updated_at) group by product` (not product+location); confirmed this product has only
  location `GP-01`, so a manual insert is safe.
- **Root cause (as far as verified):** with `record_state = 0`, a future `exitdate`, negative OH
  and no sales the item drops out of assortment eligibility; forcing a past `exitdate` +
  `record_state = 1` restores it. The query behind that exclusion was not read.

## Fix

Data-only, no PR. Postgres prod:

```sql
update exp01_ma_stylecolorchannelattributes
set exitdate = '2026_W20', record_state = 1
where product = '4b4e93fa-222e-4a50-b636-f07c78a767d3' and location = 'GP-01';
-- before: exitdate_indx 583, mkdnwks 21, record_state 0
-- after : exitdate_indx 569, mkdnwks 7,  record_state 1 (trigger recalculated)
```

Then a single-row sync to ClickHouse without waiting for the nightly: filtered `\copy` (same
column transform and `where validsizes is not null` as `export_to_ch.sql`) to a tsv, then
`clickhouse-client --query="INSERT INTO exp01_ma_stylecolorchannelattributes_tbl FORMAT CSVWithNames" < file`.

## Knowledge gained (techno-functional — required)

**Technical:** Changing `exitdate`/`record_state` on `<t>_ma_stylecolorchannelattributes` fires
`store_eligibility_triger_chetan()` (rebuilds `<t>_a_assortment`) and `update_week_indxes()`
(`*_indx`, `mkdnwks`). The CH copy of this table is refreshed only by the nightly
full reload, so ad-hoc PG fixes need either a manual single-row insert (adds a duplicate row on
the plain MergeTree) or a wait until the next daily. Check
`select location, count(*) ... group by location` first because consumers dedupe by product only.

**Functional:** An item past or near its exit week with negative inventory and no sales is treated
as exited and is hidden from assortment views, even if the exit week is still in the future.
To re-buy it, planners/support must pull the exit week into the past and set the record active
so it appears in "Add Existing Style Colors".
